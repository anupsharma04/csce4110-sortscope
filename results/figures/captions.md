- **fig06_comparisons_vs_theory.png** — Figure 6: Measured key comparisons on random input (markers) against theory (lines). (a) Selection equals n(n−1)/2 exactly; Bubble's points (rings) coincide with Selection's (on random input the early exit almost never fires, so it also makes ≈ n(n−1)/2 comparisons); Insertion tracks the inversion count ≈ n(n−1)/4. (b) Merge stays below its exact worst-case bound and close to n lg n. (c) Random-pivot Quick: the exact expectation for our partition (m+2 comparisons per partition, m+1 when the pivot is the minimum) vs the leading term 2n ln n; the gap is the +Θ(n) term. Random-pivot comparisons are for one seed per n.
- **fig07_loglog_random.png** — Figure 7: Log–log runtime on random input. Slopes are numpy.polyfit fits of log t vs log n over n ≥ 500: ≈2 indicates Θ(n²), ≈1–1.15 indicates Θ(n log n) over this range, ≈1 indicates Θ(n). Gray lines show the expected growth of each class present (c·n², c·n lg n, c·n), offset from the data by a constant factor; a measured curve of that class should run parallel to its line.
- **fig08_normalized_random.png** — Figure 8: Normalized runtime on random input. A curve that flattens means the growth model is right; its height is the hidden constant (ns per basic step). (a) is not perfectly flat: the cost per n² changes by 1.18×–1.42× from the smallest to the largest n although the comparison counts are exactly quadratic (see the slopes of comparisons) — a change in cost per operation on this machine, not extra work. (b) A curve that falls at small n is fixed per-call overhead shrinking relative to n lg n (for random-pivot Quick: one random-number call per partition, Θ(n) in total).
- **fig09_quick_pivots.png** — Figure 9: Key comparisons of the three Quick Sort pivot rules at n = 5,000 (largest size where all were run). First-element pivot is Θ(n²) on sorted and reverse input; random and median-of-three stay near n log n everywhere. Hoare partitioning keeps all three efficient on many duplicates. Log scale.
- **fig10_insertion_inversions.png** — Figure 10: Insertion Sort element shifts vs the input's inversion count (computed independently with a Fenwick tree) for every measured configuration (marker shape = input type). All points lie on y = x: each shift removes exactly one inversion. Our Insertion Sort shifts rather than swaps, so swaps are 0 and shifts are the writes minus the n−1 key placements. Sorted inputs (0 inversions, 0 shifts) cannot appear on log axes.
