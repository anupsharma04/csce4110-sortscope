# Figure captions

- **fig01_runtime_random.png** — Figure 1: Median runtime (ms, 5 trials, NullCounter) vs n on random input, linear axes. Missing points are configurations skipped by the benchmark caps (see CSV).
- **fig02_runtime_sorted.png** — Figure 2: Median runtime (ms, 5 trials, NullCounter) vs n on sorted input, linear axes. Missing points are configurations skipped by the benchmark caps (see CSV).
- **fig03_runtime_reverse.png** — Figure 3: Median runtime (ms, 5 trials, NullCounter) vs n on reverse input, linear axes. Missing points are configurations skipped by the benchmark caps (see CSV).
- **fig04_runtime_nearly_sorted.png** — Figure 4: Median runtime (ms, 5 trials, NullCounter) vs n on nearly sorted input, linear axes. Missing points are configurations skipped by the benchmark caps (see CSV).
- **fig05_runtime_many_duplicates.png** — Figure 5: Median runtime (ms, 5 trials, NullCounter) vs n on many duplicates input, linear axes. Missing points are configurations skipped by the benchmark caps (see CSV).
- **fig06_comparisons_vs_theory.png** — Figure 6: Measured key comparisons on random input (markers) against theory (lines). (a) Selection equals n(n−1)/2 exactly; Bubble's points sit under Selection's (on random input the early exit almost never fires, so it also makes ≈ n(n−1)/2 comparisons); Insertion tracks the inversion count ≈ n(n−1)/4. (b) Merge stays below its exact worst-case bound and close to n lg n. (c) Random-pivot Quick: the exact expectation for our partition (m+2 comparisons per partition, m+1 when the pivot is the minimum) vs the leading term 2n ln n; the gap is the +Θ(n) term. Random-pivot comparisons are for one seed per n.
- **fig07_loglog_random.png** — Figure 7: Log–log runtime on random input. Slopes are numpy.polyfit fits of log t vs log n over n ≥ 500: ≈2 indicates Θ(n²), ≈1–1.15 indicates Θ(n log n) over this range.
- **fig08_normalized_random.png** — Figure 8: Normalized runtime on random input. A curve that flattens means the growth model is right; its height is the hidden constant (ns per basic step). (a) does NOT flatten: cost per comparison grows ≈1.7× from n=100 to 5000 although the operation counts are exactly quadratic (see slopes of comparisons) — a per-operation cost effect of the machine, not extra work. (b) random-pivot Quick falls with n because its Θ(n) random-number calls (one per partition) shrink relative to n lg n.
- **fig09_quick_pivots.png** — Figure 9: Key comparisons of the three Quick Sort pivot rules at n = 5,000 (largest size where all were run). First-element pivot is Θ(n²) on sorted and reverse input; random and median-of-three stay near n log n everywhere. Hoare partitioning keeps all three efficient on many duplicates. Log scale.
- **fig10_insertion_inversions.png** — Figure 10: Insertion Sort element shifts vs the input's inversion count (computed independently with a Fenwick tree) for every measured configuration. All points lie on y = x: each shift removes exactly one inversion. Our Insertion Sort shifts rather than swaps, so swaps are 0 and shifts are the writes minus the n−1 key placements. Sorted inputs (0 inversions, 0 shifts) cannot appear on log axes.
